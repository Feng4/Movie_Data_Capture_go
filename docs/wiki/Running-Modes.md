# 运行模式

MDC-Go 有两个维度决定「怎么处理文件」：**运行模式**（`common.main_mode`，决定刮削多少数据）和**归档方式**（`common.link_mode`，决定文件去哪）。两者可自由组合，也可用命令行 `-mode` 临时覆盖。

## 运行模式 (main_mode)

### 模式 1: 刮削模式（默认）

完整流程：联网抓取元数据 → 下载封面/海报/剧照 → 人脸裁剪/水印 → 生成 NFO → 按命名规则归档文件。

```yaml
common:
  main_mode: 1
```

- **适合**: 初次整理、需要完整元数据的场景
- **失败处理**: 刮削失败的文件移入 `failed/`

### 模式 2: 整理模式

不访问网络，只按已有数据整理文件结构（建目录、改名、移动/链接）。

```yaml
common:
  main_mode: 2
```

- **适合**: 网络不佳时快速归类；文件名已含番号、只要目录规范化的场景
- **注意**: 仍需能识别出番号才能分组归档

### 模式 3: 分析模式

原地刮削：在文件所在目录生成 NFO 与图片，**不移动、不重命名任何文件**。

```yaml
common:
  main_mode: 3
  nfo_skip_days: 30      # NFO 近 30 天更新过的跳过
```

- **适合**: 给现有媒体库补元数据；测试配置效果
- **配套参数**: `nfo_skip_days`（跳过近期已处理）、`ignore_failed_list`（重试失败文件）
- **NFO 命名**: 与视频文件同名，保证媒体中心能自动匹配

### 模式选择速查

| 需求 | 模式 |
|------|------|
| 从头整理下载目录 | 1 |
| 无网络/快速归类 | 2 |
| 已有目录结构，补 NFO 和图片 | 3 |

## 归档方式 (link_mode)

### 0: 移动（默认）

把视频文件移动到输出目录。源目录文件减少，`del_empty_folder: true` 时自动清理空目录。

### 1: 软链接

输出目录中创建指向源文件的软链接，**原文件位置不变**。一份原始数据，多处「视图」。

- 适合: NAS 下载目录 + 独立媒体库视图，节省空间
- Windows 需管理员权限或开启开发者模式
- 模式 3 与 link_mode > 0 时，扫描会跳过失败列表中的文件（可用 `ignore_failed_list` 覆盖）

### 2: 硬链接

创建硬链接（要求源与输出在同一磁盘分区），失败时自动回退软链接。

- 适合: 同盘整理、无管理员权限的 Windows 环境
- 注意: 跨分区不可用；删源文件不影响链接，但两个链接共享同一份数据

### 归档方式速查

| 场景 | link_mode |
|------|-----------|
| 一次性归档 | 0 |
| 保留原始目录 + 建媒体库 | 1 |
| 同盘、Windows 无权限 | 2 |

## 常用组合

```yaml
# 组合 A: 全自动整理（新手默认）
common:
  main_mode: 1
  link_mode: 0

# 组合 B: 下载目录只读，软链接建库
common:
  main_mode: 1
  link_mode: 1

# 组合 C: 媒体库补元数据，一寸不动
common:
  main_mode: 3

# 组合 D: 弱网快速归类
common:
  main_mode: 2
  link_mode: 0
```
